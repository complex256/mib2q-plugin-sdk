# MHI2Q Plugin SDK — Plan 2: UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plugins get UI on the bench MHI2Q. This covers:
- an SDK-owned Plugins menu;
- a Car-menu slot;
- native-looking list/toggle pages, with a custom-drawn panel as the fallback;
- a status-line slot;
- on-screen safe-mode, wrap-loop and override indicators;
- three reference plugins: hello-menu, daemon-status and bike-rack UI.

**Architecture:**
- **Plugins describe UI declaratively.** A plugin submits a `PageSpec`, a Car-menu row or a status item, and gets user actions back on its own executor.
- **The runtime folds everything into one snapshot.** Every plugin's contribution, plus the runtime-owned Plugins menu and indicators, becomes one immutable `UiSnapshot`. It is published through a volatile reference in `mibsdk.platform.UiTable`, the `HookTable` pattern.
- **The HQC adapter renders the snapshot without shadowing any stock class.**
  - The SDK installer points the bundle list's `HMICar=` line at a new SDK activator. That activator substitutes subclasses of `CarModelBank`/`CarScreenFactory` (carplay-rgi's proven Tone pattern).
  - The subclasses add pre-allocated drawer rows, serve SDK text ids and build page screens.
  - The status line is stock partial popup 65 (LabelModel 416), written from an SDK thread.
- **Stock-thread code is minimal.** It only reads the snapshot and drops input into a bounded ring.

**Tech Stack:**
- Unchanged from Plan 1: Gradle 8.13 + `build-logic`, JDK 17/Jabel, Corretto 8/Retrolambda, Retrotranslator 1.2.9, Kotlin 2.0.21 + ProGuard, ASM 9.7, JUnit 5.10.2, Python 3.
- Daemon side: Rust (mib2q-carmqtt) and Go 1.26 (mib2q-tailscale), in their own repos.

## Global Constraints

**Bytecode and linking** (Plan 1, verbatim)
- Every class that runs on the unit is **class-file version 48**. v49/v50 are rejected by J9 2.3 even with `-noverify`. The build fails on anything else.
- Every on-unit artifact passes **LinkCheck**: call sites, field refs, type refs, class headers (super/interfaces) and catch types, against the car JCL (`java/**`, `javax/**` extracted from `$mibsdk.stockLsdJar`) plus its declared car classpath.
- The **adapter never compiles against stock compile-time constants**: no `ATTR_*`, `RT_*` or `ATTRVALIDFLAG_*` field references in `adapter-hqc/src/main`. jxe2jar constants are byte-swapped and javac inlines them. Read them at runtime via `DsiConstants`.
- **New for UI:** no qualified stock constant at all in `adapter-hqc/src/main/java/mibsdk/adapter/hqc/ui/`. This covers `TYPE_*`, `KEY_*`, `ICON_STATE_*` and any `Stock.UPPER_CASE`. Every stock id (model, screen, event, text, popup, row type) is a literal in `HqcUiIds`, taken from the `lsd-src` decompile (real values, **not** `lsd_java`, which is byte-swapped) and confirmed by a spike.

**Threads**
- Plan 1, verbatim:
  - **No plugin code ever runs on a stock thread.**
  - The configurator and the DSI proxy run on stock threads. They must never throw (catch `Throwable` and pass through) and never block (no locks, no I/O, no allocation-heavy work beyond the proxy call itself).
  - SDK-created threads are daemon threads with priority `Thread.NORM_PRIORITY - 1`.
- **New for UI.** SDK code on stock threads includes:
  - the `SdkCarActivator` constructor (LSD thread);
  - the factory overrides `getSelectionDrawers`/`getText`/`getAltText`/`createScreen` (HMIEvent);
  - SDK model listeners (HMIEvent);
  - SDK `RunnableEvent`s (HMIEvent).

  These may only:
  - read the volatile `UiSnapshot`;
  - build stock widgets from it;
  - call `UiTable.input` (drop-oldest).

  They catch `Throwable` and fall back to stock behaviour. They never log except through `RingLog.append`, and do no I/O. They take at most 50 ms.
- App-side model writes (`LabelModel.setText`, `ChoiceModel.setValue`, `ListModel` rows) happen only on the SDK thread `mibsdk-ui`.
- Widget-tree work is posted with `RunnableEvent(false, r)`, with **at most one SDK job pending** (coalesced).

**Firmware and safety** (Plan 1, verbatim)
- Supported HMI, compared as an exact string: `HMI_AU_MIB2_HQC_NAR_G22_C10_180803`, read from the `HMI = …` line of `/ifs/version_info.txt`. No match means the SDK stays off and no plugin loads.
- `bundles.properties` semantics: **every key other than `de.audi.tghu.serviceDelegateConfigurator` and `Bundle.Startup.Autostart` is treated as a bundle definition**. Never add SDK settings there; they go in `sdk.properties`.
- Never log, print or read the j9 command line (`lsd.sh` embeds the VIN and IMSI). Don't use `pidin … arg`.

**Firmware and safety (new for UI)**
- **Zero shadowed stock classes in Plan 2.** The SDK owns the `HMICar=` bundle entry. The installer:
  - writes it only if the stock line reads exactly `HMICar=de.audi.tghu.car.hmi.Activator`;
  - restores it byte for byte on uninstall;
  - refuses if any non-SDK jar in `lsd/jars` defines a class in `de/audi/tghu/car/hmi/` or `de/audi/atip/model/CarModelBank*`, because the SDK's subclasses would inherit another mod's copy (the sole-owner rule, spec §13);
  - **still refuses while carplay-rgi is present** (spec §13, unchanged).
- `SdkCarActivator` uses the stock bank and factory unless `SdkGlobals.uiEnabled`. That flag requires all of: the supported HMI, no wrap-loop latch, and `ui.enabled=true` in `sdk.properties`.
  - **Safe mode keeps the UI on**, so the Plugins menu can say so.
  - A boot with the UI on counts toward the wrap-loop latch exactly like a wrapping boot.
- Plugins can't hide or cover the reverse camera, eCall or cluster warnings: SDK UI lives only in the Car drawer, SDK pages and popup 65.

**On-unit paths** (spec §5.3, superseding Plan 1's single base dir)
- install `/mnt/app/eso/hmi/lsd/mibsdk/` (read-only at runtime);
- persist `/mnt/persist/mibsdk/` (new in Plan 2: `plugins.properties` holds the user's on/off choices; `ui-rows.properties` is used only on the S1c/S1d fallback);
- ram `/ramdisk/mibsdk/`;
- SDK jars `/mnt/app/eso/hmi/lsd/jars/`;
- log `/tmp/mibsdk.log`.

The runtime names none of them: they come from `SdkRoots`.

**Bench** (Plan 1 values + the bench run's findings)
- SSH: `ssh -o HostKeyAlgorithms=ssh-rsa -o PubkeyAcceptedKeyTypes=ssh-rsa root@10.20.0.23`. The unit lacks `date`, `tr`, `md5sum`, `cksum`, `find`, so generate files on the Mac.
- Keypanel: `http://10.20.0.23:8099` (`/status`, `/inject`, `/rotate`, `/screen.jpg`: **poll twice**, ~2 s apart).
- `mibsdk-dev restart` resets the whole unit (4–5 min). Recover the network with `ssh rpi-bench keypanel up`.
- **Never select "Start update"**, and leave the unit on its home screen after every bench step.
- `/mnt/app` is read-only at runtime; only the installer remounts it.

**Build pipeline values, repo and environment:** Plan 1's Global Constraints apply unchanged (backport string, Kotlin flags, ProGuard rules, plugin parent prefixes `java.`, `javax.`, `mibsdk.api.`, `mibsdk.compat.`, `net.sf.retrotranslator.runtime.`, authorship `complex256` / `me@complex256.dev`, no personal names or home paths in committed files, stock jars never committed). The same authorship applies to commits in `mib2q-carmqtt` and `mib2q-tailscale`.

**UI limits** (one place: `PageSpec`/`StatusItem` constants; the runtime truncates, it never throws for length)
- Page: ≤ 24 entries; title ≤ 32 chars; label ≤ 40; value ≤ 20; info ≤ 80.
- Ids: `[A-Za-z0-9._-]{1,32}`.
- Per plugin: ≤ 8 pages, ≤ 2 Car rows, ≤ 1 status item of ≤ 12 chars.
- Car drawer: 1 Plugins row + 8 plugin rows (`HqcUiIds.PLUGIN_ROW_SLOTS = 8`).
- Status line: `ui.status.max.chars` (default from spike S3b).

## Review Focus

1. **A plugin reloads, or registers late, after the Car drawer was built.** Its row must appear once and disappear when it is disabled, with no duplicate and no stale label, without an HMI restart.
   - **Test:** Task 9 `DrawerSlotsTest.reloadKeepsSlotAndNoDuplicates`.
   - **Test:** Task 5 `UiHubTest.disableRemovesRowsPagesAndStatusItem`.
2. **The plugin that owns the page on screen is disabled or quarantined.** The page must turn into a "stopped" notice. BACK must still work, and no input may reach the dead plugin.
   - **Test:** Task 5 `UiHubTest.openPageOfDisabledPluginShowsStoppedNotice`.
   - **Test:** Task 11 `PageStackTest.vanishedPageIsReplacedAndBackStillPops`.
3. **A plugin floods updates** (e.g. `StatusItem.set` 10,000 times in a loop). The HMI must stay responsive: at most one SDK job pending on HMIEvent, and model writes coalesced to the latest snapshot.
   - **Test:** Task 10 `HmiPosterTest.coalescesToOnePendingPost`.
   - **Test:** Task 5 `UiHubTest.publishCoalescesBursts`.
4. **Hostile text:** null, 10 kB, newlines, emoji, RTL marks. Nothing may throw on any thread; text is truncated and cleaned.
   - **Test:** Task 4 `UiTextTest.cleansAndTruncates`.
   - **Test:** Task 5 `UiImplTest.hostileTextNeverThrows`.
5. **More Car rows than slots** (9 plugins × 1 row, 8 slots). Assignment must be deterministic (load order), the overflowing row stays reachable from the Plugins menu, and a WARN is logged once.
   - **Test:** Task 9 `DrawerSlotsTest.overflowIsDeterministicAndReachableFromPluginsPage`.

## Decisions in this plan

[my call] marks a designer decision open to review; [decided] comes from the owner.
- [decided] One Plugins menu, plus slots for placing items elsewhere; native templates first, a custom-drawn panel as the fallback.
- [my call] **The Plugins entry is a Car-drawer row.** A main-MMI-menu entry would mean patching the table-driven SystemSMM (spec §8's named fallback).
- [my call] **Zero shadowed classes.** The SDK owns the `HMICar=` bundle entry instead of shadowing `de.audi.tghu.car.hmi.Activator`. Shadowing is the S1b fallback.
- [my call] **Status-bar slot = text in stock partial popup 65** (top-right label), not an icon cell. There is no spare status-bar cell, and adding one means shadowing `StatusbarControllerHigh`. "Icons" are short ASCII tags.
- [my call] UI stays on in safe mode (the menu explains safe mode). UI is off under the wrap-loop latch, and a UI boot counts toward the latch.
- [my call] API 2 is additive. The runtime accepts manifests with api 1–2.
- [my call] The runtime owns the indicators (`SAFE`, `LATCH`, overrides such as `PDC R OFF`) on the status line, ahead of plugin items.
- [my call] The user's on/off is persisted in `<persist>/plugins.properties`. Grants stay read-only in the menu: revocation is Plan 3 / mibpkg.
- [my call] `Reset boot guard` is the on-car gesture for leaving count-based safe mode or the latch. The `SAFE_MODE` marker can still only be cleared by `mibsdk-dev`.
- [my call] Plugins reach daemons only through `ctx.net()` (`network` permission). Raw `java.net.Socket` needs `platform.unrestricted`.
- [my call] Daemon endpoints: tailscale `127.0.0.1:19850` (sidecar), carmqtt `127.0.0.1:19851`, `key=value` lines with ages in seconds.
- [my call] Text outside Latin-1 becomes `?`. Font coverage is unknown and not worth a spike.
