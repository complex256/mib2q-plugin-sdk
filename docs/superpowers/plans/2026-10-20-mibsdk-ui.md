# MHI2Q Plugin SDK — Plan 2: UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plugins get UI on the bench MHI2Q. This covers:
- an SDK-owned Plugins menu;
- a Car-menu slot;
- native-looking list/toggle pages, with a custom-drawn panel as the fallback;
- a status-line slot;
- on-screen safe-mode and override indicators (the wrap-loop latch turns the whole SDK UI off instead);
- three reference plugins: hello-menu, daemon-status and bike-rack UI.

**Architecture:**
- **Plugins describe UI declaratively.** A plugin submits a `PageSpec`, a Car-menu row or a status item, and gets user actions back on its own executor.
- **The runtime folds everything into one snapshot.** Every plugin's contribution, plus the runtime-owned Plugins menu and indicators, becomes one immutable `UiSnapshot`. It is published through a volatile reference in `mibsdk.platform.UiTable`, the `HookTable` pattern.
- **The HQC adapter renders the snapshot without shadowing any stock class.**
  - The SDK installer points the bundle list's `HMICar=` line at a new SDK activator. That activator substitutes subclasses of `CarModelBank`/`CarScreenFactory` (carplay-rgi's proven Tone pattern; spike S1b go).
  - The subclasses add pre-allocated drawer rows, serve SDK text ids through the factory's `getText` (S1d go) and build page screens.
  - The status line is stock partial popup 65 (LabelModel 416), written from an SDK thread (S3a go).
- **Stock-thread code is minimal.** It only reads the snapshot (or an immutable drawer assignment) and drops input into a bounded ring.

## Global Constraints

**Bytecode and linking** (Plan 1, verbatim)
- Every class that runs on the unit is **class-file version 48**. v49/v50 are rejected by J9 2.3 even with `-noverify`. The build fails on anything else.
- Every on-unit artifact passes **LinkCheck**: call sites, field refs, type refs, class headers (super/interfaces) and catch types, against the car JCL (`java/**`, `javax/**` extracted from `$mibsdk.stockLsdJar`) plus its declared car classpath.
- The **adapter never compiles against stock compile-time constants**: no `ATTR_*`, `RT_*` or `ATTRVALIDFLAG_*` field references in `adapter-hqc/src/main`. jxe2jar constants are byte-swapped and javac inlines them. Read them at runtime via `DsiConstants`.
- **New for UI:** no stock constant in `adapter-hqc/src/main/java/mibsdk/adapter/hqc/ui/`: no `Q.NAME` (NAME matching `[A-Z][A-Z0-9_]+`) where Q is a fully qualified `de.…` name or a simple name the file imports from a package outside `java.`, `javax.`, `mibsdk.`. Every stock id (model, screen, event, text, popup, row type) is a literal in `HqcUiIds`, taken from the `lsd-src` decompile (real values, **not** `lsd_java`, which is byte-swapped) and confirmed by a spike.
- Platform and runtime code is Java 1.4 API: `StringBuffer`, no `codePointAt`, no try-with-resources.

**Threads**
- Plan 1, verbatim:
  - **No plugin code ever runs on a stock thread.**
  - The configurator and the DSI proxy run on stock threads. They must never throw (catch `Throwable` and pass through) and never block (no locks, no I/O, no allocation-heavy work beyond the proxy call itself).
  - SDK-created threads are daemon threads with priority `Thread.NORM_PRIORITY - 1`.
- **New for UI.** SDK code on stock threads includes:
  - the `SdkCarActivator` constructor (LSD thread, `Dispatcher-Startup`);
  - the factory overrides `getSelectionDrawers`/`getText`/`getAltText`/`createScreen` (HMIEvent);
  - SDK model listeners (HMIEvent);
  - SDK `RunnableEvent`s (HMIEvent).

  These may only:
  - read the volatile `UiSnapshot` or the volatile `SdkGlobals.uiSlots` assignment;
  - build stock widgets from it;
  - call `UiTable.input` (drop-oldest).

  They catch `Throwable` and fall back to stock behaviour. They never log except through `RingLog.append`, do no I/O, **create no thread** (spike A's activator started its probe thread in the constructor; production code must not), and take at most 50 ms.
- App-side model writes (`LabelModel.setText`, `ChoiceModel.setValue`, `ListModel` rows) happen only on the SDK thread `mibsdk-ui`, which `HqcPlatform.start()` starts.
- Widget-tree work is posted with `RunnableEvent(false, r)`, with **at most one SDK job pending** (coalesced).

**Firmware and safety** (Plan 1, verbatim)
- Supported HMI, compared as an exact string: `HMI_AU_MIB2_HQC_NAR_G22_C10_180803`, read from the `HMI = …` line of `/ifs/version_info.txt`. No match means the SDK stays off and no plugin loads.
- `bundles.properties` semantics: **every key other than `de.audi.tghu.serviceDelegateConfigurator` and `Bundle.Startup.Autostart` is treated as a bundle definition**. Never add SDK settings there; they go in `sdk.properties`.
- Never log, print or read the j9 command line (`lsd.sh` embeds the VIN and IMSI). Don't use `pidin … arg`.

**Firmware and safety (new for UI)**
- **Zero shadowed stock classes in Plan 2.** The SDK owns the `HMICar=` bundle entry. The installer:
  - writes it only if the stock line reads exactly `HMICar=de.audi.tghu.car.hmi.Activator` (the stock file has CRLF line ends; keep them);
  - restores it byte for byte on uninstall;
  - refuses if any non-SDK jar in `lsd/jars` defines a class in `de/audi/tghu/car/hmi/` or `de/audi/atip/model/CarModelBank*`, because the SDK's subclasses would inherit another mod's copy (the sole-owner rule, spec §13);
  - **still refuses while carplay-rgi is present** (spec §13, unchanged).
- `SdkCarActivator` uses the stock bank and factory unless `SdkGlobals.uiEnabled`. That flag requires all of: the supported HMI, no wrap-loop latch, the wrap boot counted (`BootGuard.countWrapBoot` returned true), and `ui.enabled=true` in `sdk.properties`.
  - **Safe mode keeps the UI on**, so the Plugins menu can say so.
  - **Under the wrap-loop latch the whole SDK UI is off**: stock drawer, no Plugins row, no status-line text, no on-car reset. The exit is `mibsdk-dev safe-mode off` over SSH. (UI wrapping itself may be what crashes the HMI.)
  - A boot with the UI on counts toward the wrap-loop latch exactly like a wrapping boot (one count per boot).
- Plugins can't hide or cover the reverse camera, eCall or cluster warnings: SDK UI lives only in the Car drawer, SDK pages and popup 65.

**On-unit paths** (spec §5.3, superseding Plan 1's single base dir)
- install `/mnt/app/eso/hmi/lsd/mibsdk/` (read-only at runtime);
- persist `/mnt/persist/mibsdk/` (new in Plan 2: `plugins.properties` holds the user's on/off choices, written with `DurableFiles.replace`);
- ram `/ramdisk/mibsdk/`;
- SDK jars `/mnt/app/eso/hmi/lsd/jars/`;
- log `/tmp/mibsdk.log`.

The runtime names none of them: they come from `SdkRoots`/`RuntimeConfig`.

**Bench** (Plan 1 values + the bench runs' findings)
- SSH: `ssh -o HostKeyAlgorithms=ssh-rsa -o PubkeyAcceptedKeyTypes=ssh-rsa root@10.20.0.23`. The unit lacks `date`, `tr`, `md5sum`, `cksum`, `find`, so generate files on the Mac.
- Keypanel: `http://10.20.0.23:8099` (`/status`, `/inject`, `/rotate`, `/screen.jpg`: **poll twice**, ~2 s apart).
- `mibsdk-dev restart` resets the whole unit (4–5 min). The unit loses its DHCP lease on every restart: run `ssh rpi-bench keypanel up`.
- After a drawer row press the drawer closes in ~8.5–9 s and further input falls through to drive select: act within 8 s or reopen the drawer, and check drive select is still on Dynamic afterwards.
- **Never select "Start update"**, and leave the unit on its home screen after every bench step. Never power the bench on yourself.
- `/mnt/app` is read-only at runtime; only the installer remounts it.

**Build pipeline values, repo and environment:** Plan 1's Global Constraints apply unchanged (backport string, Kotlin flags, ProGuard rules, plugin parent prefixes `java.`, `javax.`, `mibsdk.api.`, `mibsdk.compat.`, `net.sf.retrotranslator.runtime.`, authorship `complex256` / `me@complex256.dev`, no personal names or home paths in committed files, stock jars never committed). The same authorship applies to commits in `mib2q-carmqtt` and `mib2q-tailscale`.
- Before every commit: `./gradlew check` and `python3 -m unittest installer/test_mibsdk_dev.py installer/test_gen_bundles.py` pass (car-readiness convention). Commit with `git add <paths> && git commit` (new files are never staged by `-am`).
- Plugin jars for the unit are built with `./gradlew :plugins:<id>:mibPluginJar`, which writes `<id>.jar.stamp` (`CheckStamp` format 1); `mibsdk-dev push` refuses an unstamped or stale jar. The unit jars come from `./gradlew :dist:assembleUnit` (`mibsdk-unit.stamp`).

**UI limits** (one place: `PageSpec`/`StatusItem` constants; the runtime truncates text, it never throws for length; exceeding a *count* limit throws `IllegalStateException`)
- Page: ≤ 24 entries; title ≤ 32 chars; label ≤ 40; value ≤ 20; info ≤ 80.
- Ids: `[A-Za-z0-9._-]{1,32}`. The plugin id `mibsdk` is reserved (runtime pages use owner `mibsdk`).
- Per plugin: ≤ 8 pages, ≤ 2 Car rows, ≤ 1 status item of ≤ 12 chars.
- Car drawer: 1 Plugins row + 8 plugin rows (`HqcUiIds.PLUGIN_ROW_SLOTS = 8`).
- Status line: `ui.status.max.chars`, default 24 (S3b).

`UiText.clean(s, max)` [decided by preflight]:
- `null` → `""`; control chars (`< 0x20`, `0x7F–0x9F`) → space; whitespace runs collapse to one space; trimmed;
- format/bidi marks U+200B–U+200F, U+202A–U+202E, U+2060–U+2064, U+FEFF are dropped;
- a surrogate pair → one `?` (manual `Character`-free high/low range test); a lone surrogate → `?`; any other char > U+00FF → `?`;
- longer than `max` → first `max - 3` chars + `...` (for `max ≤ 3`, a hard cut).

3. **A plugin floods updates** (e.g. `StatusItem.set` 10,000 times in a loop). The HMI must stay responsive: at most one SDK job pending on HMIEvent, and model writes coalesced to the latest snapshot; an open request made while a job is pending is not lost.
   - **Test:** Task 10 `HmiPosterTest.coalescesToOnePendingPost`, `UiApplierTest.openRequestDuringPendingJobIsNotLost`.
   - **Test:** Task 5 `UiHubTest.publishCoalescesBursts`.

   - **Test:** Task 4 `UiTextTest.cleansAndTruncates`.
   - **Test:** Task 5 `UiImplTest.hostileTextNeverThrows`.
5. **More Car rows than slots** (9 plugins × 1 row, 8 slots). Assignment must be deterministic (load order), the overflowing row stays reachable from the Plugins menu, and a WARN is logged once per overflowing row.
   - **Test:** Task 9 `DrawerSlotsTest.overflowIsDeterministic`.

```java
public interface Ui {
  /** Registers a page under this plugin's Plugins-menu entry; actions arrive on the plugin's executor. */
  Page page(PageSpec spec, Listener<UiAction> onAction);
  /** A row in the Car menu that opens {@code opens}. Needs ui.slot.carmenu and Features.SLOT_CAR_MENU. */
  Subscription carMenuRow(String label, Page opens);
  /** One short status-line item; set(null|"") hides it. Needs ui.slot.statusbar and Features.SLOT_STATUS_BAR. */
  StatusItem statusItem(String text);
}
public interface Page extends Subscription { String id(); void update(PageSpec spec); /** shows it now */ void open(); }
```

## Decisions in this plan

[my call] marks a designer decision open to review; [decided] comes from the owner or a recorded ruling.
- [decided] One Plugins menu, plus slots for placing items elsewhere; native templates first, a custom-drawn panel as the fallback.
- [my call] **The Plugins entry is a Car-drawer row.** A main-MMI-menu entry would mean patching the table-driven SystemSMM (spec §8's named fallback).
- [my call] **Zero shadowed classes.** The SDK owns the `HMICar=` bundle entry (S1b go; no shadow fallback needed).
- [my call] **Status-bar slot = text in stock partial popup 65** (top-right label), 24 chars. "Icons" are short ASCII tags.
- [decided] Labels come from the factory's `getText`; model-bound (`%1`) labels are not used anywhere (S1d).
- [decided] UI stays on in safe mode (the menu explains it). **Under the wrap-loop latch the whole SDK UI is off** — no Plugins row, no indicator, no on-car reset; the exit is `mibsdk-dev safe-mode off` (or `boot-state`) over SSH. A UI boot counts toward the latch once.
- [decided] The on-car `Reset boot guard` item exists only for count-based safe mode. The `SAFE_MODE` marker is cleared only by `mibsdk-dev`.
- [my call] API 2 is additive. The runtime accepts manifests with api 1–2; the id `mibsdk` is reserved.
- [my call] The runtime owns the indicators (`SAFE`, overrides such as `PDC R OFF`, shown while held **and** while restoring) on the status line, ahead of plugin items.
- [decided] UI features (`slot.carmenu`, `slot.statusbar`, `ui.pages`) are fixed for the boot (from `uiEnabled`); there is no API event. `UiImpl` still reads `LiveFeatures` at call time.
- [my call] The user's on/off is persisted in `<persist>/plugins.properties` via `DurableFiles`. Grants stay read-only in the menu: revocation is Plan 3 / mibpkg.
- [my call] Plugins reach daemons only through `ctx.net()` (`network` permission), **loopback only**. Raw `java.net.Socket` needs `platform.unrestricted`.
- [my call] Daemon endpoints: tailscale `127.0.0.1:19850` (sidecar), carmqtt `127.0.0.1:19851`, `key=value` lines with ages in seconds.
- [my call] Text outside Latin-1 becomes `?`. Font coverage is unknown and not worth a spike.
- [decided] M6 belongs to the car-readiness plan; the bike-rack UI builds on its in-memory arm.
- [decided] The installer's owned-class prefixes are a constant in `mibsdk-dev`, not a dist file.
